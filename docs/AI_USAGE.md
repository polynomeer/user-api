# AI 활용 내역

> 방법론 정리: [09-ai-methodology](09-ai-methodology.md)
>
> 안내 메일: "코딩테스트에서 AI는 활용 가능하며 어떤 툴을 사용하셨는지만 알려주시면 됩니다."

## 사용 도구

| 도구 | 모델 | 용도 |
|---|---|---|
| Claude Code (데스크톱 앱) | Claude Opus 5.5 | 요구사항·데이터 분석, 설계 문서 초안, 코드 작성 보조, 테스트 케이스 도출 |

## 활용 원칙

- AI 산출물은 직접 검토·수정 후 반영하며, 설계 결정의 최종 판단은 본인이 한다
- AI가 참여한 커밋에는 `Co-Authored-By` 트레일러를 남겨 이력을 투명하게 한다
- 규칙을 프롬프트가 아닌 하네스로 강제한다 (`.claude/`)
  - `settings.json`: `user.txt` 수정 차단(deny), 응답 종료 시 소스 변경이 있으면 `./gradlew test` 실행·실패 시 종료 차단(Stop 훅)
  - 서브에이전트: `spec-reviewer`(요구사항·설계 대조), `test-planner`(테스트 계획 누락 탐지), `submit-checker`(제출 체크리스트 실행) — 모두 읽기 전용 검증 역할
  - 스킬: `/step N`(단계 구현→검증→커밋 절차 고정), `/checklist`(제출 전 점검)

| 2. 파서 | 테스트 케이스 도출 및 테스트 선작성(TDD), `UserLineParser`·`ParseResult` 등 구현 | 검증 규칙·에러 코드 검토, `+1`/int 초과 등 경계 케이스 확인 |
| 3. 로더·저장소 | 로더·스냅샷 저장소·기동 시 적재 구현, 로더/재적재 테스트 작성, 실제 기동 로그 확인 | 부작용 있는 switch guard를 명시적 분기로 수정, 파일 없음 기동 시나리오 확인 |
| 4. 조회 API | MockMvc 테스트 선작성, 컨트롤러·서비스·페이징 DTO 구현, curl로 실제 응답 확인 | 테스트 기대값 재계산(마지막 페이지 첫 ID 1034→1033 수정), page×size 오버플로 케이스 검토 |
| 5. 재적재 API | 재적재 API 테스트 선작성·구현, 명세 검증 서브에이전트 실행, 복사본 파일로 curl 시나리오(추가·삭제·복구) 확인 | 응답에 서버 경로 미노출 결정, GET /reload가 /{id}에 매칭되는 동작 검토 후 설계 유지 |
