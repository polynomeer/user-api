## 3. 단계별 상세

### 0. 분석·설계 (`d7a6ac9`)

**한 일**
- 과제 PDF와 `user.txt`를 분석해 요구사항(FR-1~8, NFR-1~4)과 명세에 없는 부분의 가정(A-1~A-10)을 문서화
- 데이터 특이사항 발견: 40행, **CRLF 줄바꿈, 마지막 행 개행 없음**, 오류 행 3건(16: 연봉의 영문 `O`, 31: 빈 필드 `,,`, 39: 연봉의 `AAA`)
- 기대 결과(성공 37 / 실패 3)를 테스트 기준값으로 확정
- 90분 일정, 컷라인(Must/Should/Could), 제출 체크리스트, 커밋 규칙, Claude Code 지침(`CLAUDE.md`) 작성

**판단**
- 구현 전에 설계를 확정: 제한 시간 안에서 범위가 흔들리는 것이 가장 큰 위험이라 판단
- 오류 행은 자동 보정하지 않고 실패로 기록(A-3): 보정은 데이터 오류를 숨김
- 재적재는 불변 스냅샷 통째 교체로 설계: 재적재 중 조회 일관성(NFR-3)과 실패 시 데이터 유지(NFR-2)를 한 번에 해결
- 기동 시 파일이 없어도 기동(A-8): 재적재 API로 복구 가능하므로 가용성 우선
- 과제 원본(pdf/png)은 공개 레포에 올라가지 않도록 `.gitignore` 처리

### 1. 스캐폴딩 (`931fa07`)

**한 일**: start.spring.io로 프로젝트 생성, `application.yml`에 데이터 파일 경로 설정 분리, `.gitattributes`로 `user.txt` 줄바꿈 변환 금지

**문제와 대응**
- 프로젝트 생성 서버가 Actuator 포함 시·버전 명시 시 500 오류 → Actuator는 필수가 아니어서 제외, 기본 버전(4.1.1)으로 생성
- `user.txt`의 CRLF 자체가 검증 대상인데 git이 줄바꿈을 바꿀 수 있음 → `-text` 속성으로 고정
- FR-8(실행 중 파일 변경 반영) 때문에 classpath가 아닌 **파일시스템 경로**로 읽도록 설정값 분리

### 2. 파서 (`12bd0d7`)

**한 일**: `UserLineParser`(순수 클래스), `ParseResult`(sealed: Success | Failure), `ParseErrorCode`. 테스트 29건을 **먼저 작성해 Red 확인 후** 구현

**판단**
- 예외 대신 결과 값 반환: 잘못된 행은 예상된 입력이며, 한 줄 실패가 전체 적재를 멈추면 안 됨
- `Integer.parseInt`가 `+1`, `-1`을 허용하는 점을 테스트로 발견 → 숫자 패턴(`\d+`)으로 먼저 거른 뒤 변환
- 연봉 `_`는 3자리 단위만 허용(`1__000`, `10_00` 거부): 구분자로 의미 있는 형태만 받아 오타 검출

### 3. 로더·저장소 (`277af2d`)

**한 일**: `UserFileLoader`(줄 단위 UTF-8 읽기, skip 규칙, 중복 ID, 로그), `UserSnapshot`(불변), `UserRepository`(`AtomicReference`), `UserService.reload()`(`synchronized`), `UserDataInitializer`(기동 시 적재)

**검토 중 수정**
- AI가 작성한 중복 ID 처리가 `switch` guard 안에서 `seenIds.add()`(부작용)를 호출 → 읽는 사람이 놓치기 쉬워 **명시적 if/else로 수정**

**검증**: 테스트 8건(CRLF/LF·BOM·EUC-KR 파일·파일 없음 포함), 실제 기동 로그 확인, 존재하지 않는 경로로 기동해 ERROR 로그 후 정상 기동 확인

### (하네스 구성) (`e48ab49`)

AI가 규칙을 "지켜주길 바라는" 대신 도구가 강제하도록 Claude Code 하네스를 구성했다. 상세는 4절.

**문제와 대응**
- 처음엔 Stop 훅이 `src` 전체 변경을 감지 → 4단계에서 **테스트만 먼저 작성한 Red 상태에서도 종료가 막힘**
- 검사 대상을 `src/main`으로 좁혀, Red 단계는 허용하고 프로덕션 코드 변경 후에는 테스트 통과를 강제
- 이 수정은 AI가 자기 감시 훅을 바꾸는 행위라 자동 권한 검사에서 차단됨 → **사용자 명시 승인 후** 수정
- 다른 작업(4단계)이 스테이징된 상태여서, 하네스 변경만 별도 커밋으로 분리해 단계 커밋이 섞이지 않게 함

### 4. 조회 API (`90bcd93`)

**한 일**: 목록(페이징)·단건·이름 검색·파싱 실패 조회. MockMvc 테스트 10건 선작성

**판단**
- 범위를 넘는 page는 에러가 아닌 빈 `content`
- `page * size`를 `long`으로 계산: `page=Integer.MAX_VALUE` 같은 요청에서 int 오버플로 방지
- 각 조회는 스냅샷을 **한 번만** 읽어 처리: `totalElements`와 `content`가 다른 버전에서 나오지 않게 함

**검토 중 수정**: 테스트 기대값 재계산 과정에서 마지막 페이지 첫 ID를 1034→1033으로 정정

**남긴 과제**: 잘못된 파라미터의 400 응답이 아직 Spring 기본 형식 → 6단계로 미룸

### 5. 재적재 API (`87fd2c3`)

**한 일**: `POST /api/users/reload`. 파일을 읽지 못하면 500 `DATA_LOAD_FAILED`, 기존 데이터 유지

**판단**
- 500 응답에 서버 파일 경로를 노출하지 않음: 경로는 로그에만
- 재적재 테스트를 조회 테스트와 분리: 데이터 파일을 수정하므로 같은 컨텍스트를 공유하면 순서에 따라 결과가 바뀜
- `GET /api/users/reload`가 405가 아닌 400이 되는 현상 발견(`/{id}`에 매칭) → 경로를 숫자로 제한하면 `/api/users/abc`가 설계(400)와 달리 404가 되므로 **설계 유지**

**검증**: 명세 검증 서브에이전트 대조(누락 없음), 복사본 파일로 추가→반영(38건)→삭제→500·데이터 유지→복구 시나리오 curl 확인

### 6. 예외 처리 (`8a99b75`)

**한 일**: `ResponseEntityExceptionHandler` 상속 핸들러로 모든 에러를 `ProblemDetail` + `code` + 한글 `detail`로 통일. 에러 테스트 17건

**검토 중 발견한 버그**
- 스프링 표준 예외(406 등)의 대체 경로에서 `code`가 붙지 않음 → 상위 클래스가 본문을 `super` 호출 **안에서** 생성하기 때문. 호출 이후에 본문을 보정하도록 수정 (명세 검증 서브에이전트의 제안으로 대체 경로 테스트를 추가하다 발견)

**판단**
- 검증 메시지를 제약 선언에 한글로 직접 지정: 서버 Locale에 따라 기본 메시지가 바뀌는 것 방지
- 클라이언트 입력값은 `detail`에 되돌려 주되 50자로 제한

### 7. 테스트 보강 (`dd4a8d8`, `fe5e292`)

**한 일**: JaCoCo 도입. 동시성(재적재 200회 중 4스레드 조회), 파일 없이 기동, 페이징 경계값, 스냅샷 불변성 테스트

**판단**
- 커버리지 수치가 아닌 **"증명되지 않은 동작"** 기준으로 보강: 라인 191/193(99%)이었고 남은 분기는 도달 불가능한 방어 코드
- 동시성 테스트가 정말 결함을 잡는지 **뮤테이션으로 확인**: 스냅샷을 두 번 읽도록 고의로 바꾸면 3회 모두 실패 → 원복

**검증 지적 수용** (`fe5e292`)
- FR-3("파싱 실패는 로그를 남긴다")을 결과 객체로만 검증하고 로그 출력은 검증하지 않았음 → 로그 캡처 테스트 추가
- 이전 커밋에서 동시성 테스트가 "실제 겹침을 보장한다"고 쓴 것은 **과장**이었음 → 테스트가 증명하는 것과 못 하는 것을 문서에 정정 기록

### 8. 마무리 (`e864b84`)

**한 일**: README 전면 작성(실행법, API·실제 응답 예시, 에러 코드, 데이터 처리 규칙, 설계 결정, 테스트, AI 도구)

**판단**: 응답 예시는 실제 기동한 앱의 응답으로 작성. 실제 응답에 없는 `type` 필드는 예시에서 제거. README의 curl 5개를 그대로 실행해 확인

### 추가 문서·하네스 (`0be0b12`, `712ce0c`, `d750faa`)

- **운영 확장 설계**: 패키지 전면 재배치를 검토했으나, 테스트 80건이 있는 마무리 시점에서 회귀 위험 대비 이득이 작다고 판단 → 코드는 유지하고 목표 구조(포트-어댑터)와 확장 포인트만 문서화

## 4. AI 활용 방식

### 4.1 컨텍스트 설계

- `CLAUDE.md`에 과제 개요, 읽을 문서, 명령어, 규칙(커밋 규칙, `user.txt` 불변, 코드 스타일, 파서 원칙)을 정리
- "현재 단계만 작업하고 범위를 넓히지 말 것", "설계와 다르게 구현하려면 먼저 이유를 말할 것"으로 AI의 임의 확장을 제한

### 4.2 하네스 (`.claude/`)

| 구성 | 역할 |
|---|---|
| 권한 deny | `user.txt` 수정 차단 |
| 권한 allow | gradle·curl·git 명령 확인 생략 (시간 절약) |
| Stop 훅 | 프로덕션 코드 변경 시 테스트 실패 상태로 작업 종료 불가 |
| commit-msg 훅 (로컬) | 커밋 규칙 필수 섹션 누락 시 거부 |
| `spec-reviewer` | 커밋 전 요구사항·설계 대조 (읽기 전용) |
| `test-planner` | 테스트 계획 대비 누락 케이스 탐지 (읽기 전용) |
| `submit-checker` | 제출 체크리스트 실행 (읽기 전용) |
| `code-reviewer` | 코드 품질 리뷰 (읽기 전용) |
| `/step N`, `/checklist` | 단계 진행·제출 점검 절차 고정 |

**원칙**: 서브에이전트는 **검증만** 담당하고 구현은 메인 세션에서 직접 검토하며 진행. 인터뷰에서 모든 코드를 설명할 수 있어야 하기 때문.

### 4.3 AI 산출물을 검토해 바꾼 사례

| 단계 | AI 산출물 | 검토 결과 |
|---|---|---|
| 3 | 부작용 있는 `switch` guard | 명시적 if/else로 수정 |
| 4 | 마지막 페이지 기대값 1034 | 재계산해 1033으로 정정 |
| 5 | `GET /reload`가 400이 되는 현상의 해결안(`/{id}` 숫자 제한) | `/api/users/abc`가 404로 바뀌어 설계(400) 위반 → 기각, 설계 유지 |
| 6 | 대체 경로 예외 처리 | `code` 누락 버그 발견·수정 |

| 하네스 | Stop 훅 검사 범위 | TDD Red 단계를 막는 문제 발견 → 범위 축소 |

## 6. 회고

**잘된 점**
- 설계를 먼저 확정해 구현 중 범위가 흔들리지 않았고, 단계마다 커밋으로 진행 상태가 명확했음
- 원자적 스냅샷 교체 설계 덕분에 재적재·동시성·실패 시 유지 요구사항을 한 구조로 해결
- 커밋 바디에 판단 근거를 남겨 커밋 이력만으로 의사결정을 재구성할 수 있음

**아쉬운 점·개선할 점**
- 하네스를 과제 도중(4단계 직전)에 구성해 초기 단계에는 적용되지 않았음 → 착수 전 미리 준비했어야 함
- Stop 훅 범위를 처음부터 TDD 흐름에 맞춰 설계하지 못해 한 번 수정이 필요했음
- 동시성 테스트는 "조회 도중 교체"를 직접 증명하지 못함 (한계를 문서화하고 뮤테이션 확인으로 보완)
- 운영 구조(포트-어댑터)는 시간상 문서로만 남김
