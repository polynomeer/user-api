# 01. 요구사항 분석

> 출처: 과제 PDF, 안내 메일 이미지(레포 미포함). 원문 요약이며, 해석·가정은 별도 표기한다.

## 1. 진행 조건 (안내 메일)

| 항목 | 내용 |
|---|---|
| 제한 시간 | 문서 전달 후 **1시간 30분** 이내 메일 제출 (문서 확인 + 구현 + 제출 포함) |
| 제출 형식 | zip 파일 또는 개인 레포지토리 중 택1 |
| AI 사용 | **허용**. 단, 사용한 도구를 명시해야 함 → [`AI_USAGE.md`](AI_USAGE.md) |
| 평가 관점 | 기능 완성도 + 개발 역량·사고 방식. 대면 인터뷰에서 **진행 과정까지 검증** |
| 평가 목적 | 집중력, **에러 대응 및 예외처리**, 코딩 스타일 |

→ 진행 과정 검증에 대비해 **작은 단위 커밋 + 상세한 한글 커밋 바디**로 의사결정 이력을 남긴다.

## 2. 기능 요구사항

| ID | 요구사항 | 비고 |
|---|---|---|
| FR-1 | Spring Boot 기반 RESTful API | |
| FR-2 | 기동 시 `user.txt`를 읽어 `User`로 변환 후 메모리 적재 | 힙 메모리(Map/List 등) 사용 가능 |
| FR-3 | 파싱 중 에러가 난 부분은 **로그**를 남김 | |
| FR-4 | 전체 User 목록 **페이지 단위** 조회 (JSON) | |
| FR-5 | **ID**로 특정 User 조회 (JSON) | |
| FR-6 | **이름에 포함된 문자열**로 User 검색 (JSON) | 부분 일치 |
| FR-7 | **파싱 실패 데이터**를 별도 조회하는 API | FR-3의 로그와 별개로 메모리에도 보관해야 함 |
| FR-8 | 실행 중 변경된 `user.txt`를 **다시 읽어 메모리 갱신**하는 API | 런타임 변경 → classpath가 아닌 파일시스템 경로 사용 |

## 3. 비기능 요구사항 (평가 목적에서 도출)

| ID | 요구사항 |
|---|---|
| NFR-1 | 잘못된 입력(데이터 파일·요청 파라미터)에 대해 일관된 에러 응답과 적절한 HTTP 상태 코드 |
| NFR-2 | 파일 없음/읽기 실패 등 I/O 오류 시 애플리케이션이 죽거나 기존 데이터를 잃지 않음 |
| NFR-3 | 재적재 중 조회 요청이 들어와도 **부분 갱신된 상태가 노출되지 않음** (원자적 교체) |
| NFR-4 | 읽기 쉬운 계층 구조, 일관된 네이밍, 테스트로 동작 증명 |

## 4. 가정 및 해석 (명시되지 않은 부분)

| # | 가정 | 근거 |
|---|---|---|
| A-1 | 파일 인코딩은 UTF-8, 구분자는 `,`, 각 필드는 앞뒤 공백 trim | 샘플 데이터 형식 |
| A-2 | 연봉의 `_`는 Java 숫자 리터럴처럼 **자릿수 구분자**로 허용 (`30_000_000` → 30000000) | 전 데이터가 이 형식 |
| A-3 | 필드 수가 정확히 5개가 아니면 실패 처리 (빈 필드 `,,` 자동 보정 안 함) | 데이터 임의 보정은 오류 은폐 위험 |
| A-4 | 성별은 `M`/`F`만 허용 | 샘플 데이터 기준 |
| A-5 | ID 중복 시 **먼저 나온 행 유지**, 이후 행은 실패 처리 | 데이터 유실보다 명시적 실패가 안전 |
| A-6 | 빈 줄은 실패가 아닌 skip. 구분선(`====`)도 skip. 헤더(`ID , 이름 ...`)는 **첫 데이터 행 이전에만** skip하고, 이후의 `ID ,`로 시작하는 행은 ID가 깨진 데이터로 보고 실패 처리 | PDF 데이터 설명에 헤더가 존재. 위치 제한이 없으면 깨진 데이터 행이 조용히 사라짐 |
| A-7 | 재적재 실패(파일 없음 등) 시 **기존 데이터 유지** 후 에러 응답 | NFR-2 |
| A-8 | 기동 시 파일이 없어도 애플리케이션은 기동(빈 데이터 + ERROR 로그), 재적재 API로 복구 가능 | 가용성 우선. 대안: fail-fast |
| A-9 | 페이지 번호는 0부터 시작, 기본 size 10, 최대 100 | Spring Data 관례 |
| A-10 | 정렬은 ID 오름차순 | 결정적 페이지 결과 보장 |
