# 04. 샘플 데이터(`user.txt`) 분석

## 1. 파일 특성

| 항목 | 값 | 구현 시 고려 |
|---|---|---|
| 행 수 | 40행 (ID 1001~1040) | |
| 인코딩 | UTF-8 (한글 이름) | `StandardCharsets.UTF_8` 명시 |
| 줄바꿈 | **CRLF (`\r\n`)** | `BufferedReader.readLine()`은 CRLF 처리 가능. `split("\n")` 사용 금지 |
| 파일 끝 | 마지막 행에 **개행 없음** + **후행 공백** | 필드 trim 필수 |
| 구분자 | ` , ` (공백 포함 콤마) | `split(",", -1)` 후 trim (`-1`로 빈 필드 보존) |
| 헤더 | 없음 (PDF 설명에는 헤더/구분선 존재) | 헤더·구분선 skip 로직 둠 (A-6) |
| ID 중복 | 없음 | 중복 검사 로직은 둠 (A-5) |

## 2. 의도적으로 심어진 오류 행

| 행 | 원본 | 문제 | 기대 처리 |
|---|---|---|---|
| 16 | `1016 , 바사삭 , 38 , F , 45_OOO_000` | 연봉의 `0`이 영문 대문자 `O` | 실패: `INVALID_SALARY` |
| 31 | `1031 , 일본 , 53 , F ,, 60_000_000` | 빈 필드로 필드 수 6개 | 실패: `INVALID_FIELD_COUNT` |
| 39 | `1039 , 농심 , 61 , M , 68_AAA_000` | 연봉에 `AAA` | 실패: `INVALID_SALARY` |

→ 기대 결과: **성공 37건 / 실패 3건**. 이 수치를 통합 테스트의 기준값으로 사용한다.

## 3. 추가로 방어할 케이스 (샘플엔 없지만 재적재 시 들어올 수 있음)

| 케이스 | 예 | 처리 |
|---|---|---|
| 숫자 필드 비숫자 | `abc , 홍길동 , 20 , M , 1_000` | `INVALID_ID` |
| 정수 범위 초과 | 연봉 `9_999_999_999` | `INVALID_SALARY` (int overflow → `NumberFormatException`) |
| 음수/0 ID | `-1 , ...` | `INVALID_ID` |
| 비정상 나이 | `-3`, `200` | `INVALID_AGE` (허용 범위 0~150) |
| 잘못된 성별 | `X`, `남` | `INVALID_GENDER` |
| 빈 이름 | `1050 ,  , 20 , M , 1_000` | `INVALID_NAME` |
| 잘못된 구분자 위치 | `1__000`, `_1000`, `1000_` | `INVALID_SALARY` (정규식 `^\d{1,3}(_\d{3})*$` 또는 `^\d+$`) |
| 중복 ID | 같은 ID 두 번 | 두 번째 행 `DUPLICATE_ID` |
| BOM | 파일 선두 `﻿` | 첫 행에서 제거 |
| 빈 줄 | `""`, `"   "` | skip (실패 아님) |
